# algolia-search — decisions

The choices that shape this repository, one line each, with where the full
reasoning lives. Superseded decisions stay listed, marked, so the history
reads in order.

| # | Decision | Why | Source |
|---|---|---|---|
| 1 | Upstream's `query(text, params)` kept at every call site, run on one `pg` Client per request (a WeakMap keyed by the request's ExecutionContext, connected once), Hyperdrive's connection string first, upstream's own `pg.Pool` over `POSTGRES_URL` as the fallback without a Cloudflare context | The Workers runtime refuses to share a socket across requests; Hyperdrive pools on Cloudflare's side; the template's queries stay as written | `specs/epics/algolia-search/design.md` §2, risk AL-A |
| 2 | `pg` (the template's driver) to Supabase Postgres through Hyperdrive, not Supabase's PostgREST client; upstream's `ssl` override dropped | The template's product page is a plain SQL read; the Worker talks to Hyperdrive, which talks TLS to Supabase | design.md §2 |
| 3 | `pg-cloudflare` shipped whole through `outputFileTracingIncludes` | `pg` is a Next server-external package, so the build traces it for Node and copies only pg-cloudflare's empty default export; OpenNext's bundler resolves its `workerd` export | risk AL-K |
| 4 | The Algolia application id and search-only key are the Worker's SECRETS, read per request and handed to InstantSearch as props — not `NEXT_PUBLIC_` variables inlined at build | No SaaS key is ever in an Orun build; a key added or rotated reaches the Worker on the next deploy, with no rebuild of a bundle that holds it | design.md §3, risk AL-B |
| 5 | The secrets are optional: unset, the home page keeps the template's notice and lists the catalogue from Postgres under it | A product goes live before its owner has an Algolia application; the born site still shows its data and every product page works | design.md §3 |
| 6 | The index is filled by Algolia's own Supabase connector, configured in Algolia's dashboard with the template's `demo/transform.js` — an owner's one-time step, not a deploy hook or app code | As upstream: the connector reads the database directly; nothing in the product needs the write/admin key | risk AL-C |
| 7 | Upstream's `demo/seed.sql` is two migrations: its CREATE TABLE (010) and its twenty upserts (030), byte for byte, applied by `db-migrate` before the Worker deploys | Upstream had you paste it into the SQL Editor; a bootstrap is unattended, and the catalogue and the connector need data from the first deploy | design.md §2 |
| 8 | A local database is migrated by `apps/web/scripts/migrate.mjs` over the same files (`pnpm db:migrate`), its ledger (with each file's sha256) in schema `local_migrations` | One copy of the schema and the data; nothing of the migrator's lands in `public` | design.md §2 |
| 9 | Row-level security on every table in `public`, with no policy | Supabase's Data API serves `public` to the public anon key — the internal-only cost prices, suppliers and notes included; the app connects as the table's owner | risk AL-E |
| 10 | The rebrand's leftover sweep allows exactly Algolia's names `ALGOLIA_SEARCH_API_KEY` and `NEXT_PUBLIC_ALGOLIA_SEARCH_API_KEY` | This baseline's env-var prefix (`ALGOLIA_SEARCH_`) is also Algolia's own spelling for its search key; any other use of the prefix still fails | `tooling/rebrand/rebrand.mjs` (`ALGOLIA_NAMES`), `testing/rebrand.test.sh`, risk AL-F |
| 11 | `wrangler.jsonc` committed as the fixture render; stage and prod re-render it from their wiring document | The composition checks for it before the build | design.md §4 |
| 12 | One landing (`01-product`) then the record (`02-docs`); every edge `mode: enforced` on main, advisory on a pull request | One convergence runs supabase → cloudflare-hyperdrive → db-migrate → web per environment | design.md §4 |
| 13 | The migrations package is named `@saas/db` | stack-tectonic's db-migrate composition builds `--filter=@saas/db` | risk AL-H |
| 14 | Geist through the `geist` package (next/font/local), not `next/font/google` | Google's font download fails on GitHub's runners | IMPLEMENTATION-STATUS |
| 15 | `ci.yml` plans nothing while `intent.yaml` names `ws_CHANGE_ME` (the `linked` step) | A bootstrap cannot set a repository variable | `.github/workflows/ci.yml` |
| 16 | stack-tectonic 0.19.0; orun pinned only where it runs (the `orun-action` `version:` in each workflow); no kiox | postgres-drizzle-starter's proven pins | `intent.yaml`, `.github/workflows/` |
| 17 | Component docs are generated from the manifests and checked in CI | A hand-written copy of the dependency graph, bindings and migrations drifts silently | `tooling/catalog/gen-component-docs.py` |
| 18 | The console card reads `subdomain` from the Cloudflare connection and asks for no domain and no Algolia key; an empty `productdomain` brands the placeholder `<reponame>.example.com` | The subdomain has one right answer; the app goes live on workers.dev, and attaching a domain or connecting Algolia is an owner's step | `blueprint.yaml`, `repo-blueprint.yaml`, `tooling/rebrand/rebrand.mjs` |
| 19 | The e2e runs the search in a headless Chrome against an Algolia stand-in, and needs a Chrome to run at all | InstantSearch is client-only: the server renders no search markup, so only a browser proves it searches with what the Worker handed it | `testing/e2e.test.sh`, risk AL-I |
| 20 | The turso-starter v8 shape on orun v2.88.0: no `checks.yml`; the brokered keys in one `secrets` reconcile per provider; the task set-up in the background, each landing checked in the box (`checks: local`), the watch at 5 s | The fast bootstrap shape every starter shares | `repo-blueprint.yaml`, `testing/phases.test.sh`, `testing/coverage.test.sh` |
